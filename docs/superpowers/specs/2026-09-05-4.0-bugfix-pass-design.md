Parent specs this implements (does not reopen): pairing foundation

## Problem

v4.0.x cut over to Noise pairing + per-device tokens. Crypto and token verify
fail closed, but eight operator-facing holes remain: pairing URL defaults
disagree across clients and docs; `tether pair` does not print the QR the docs
promise; revoke deletes a registry row and leaves the live shell and push row;
Noise terminals are always `focused`, so a backgrounded phone suppresses
waiting push; IK `unauthorized` is a device-existence oracle; group-tab kill
copy is singular; iOS 401 remint is only on session REST; `tether device token`
enrolls a ghost device with no help text; leftover password comments and the
3.x lockout are undocumented.

## Goals

Locked with the operator:

1. A typed pairing address means the same thing on iOS, desktop, and in docs.
2. `tether pair` prints a QR the in-app scanner already understands.
3. Revoke drops that device’s live channels (PTY holders stay) and its push
   rows.
4. Revoking the last device warns and proceeds.
5. Noise carries per-session `{t:'focus', id, focused}` (WS semantics on a muxed channel).
6. Unauthorized IK is indistinguishable from a handshake failure on the wire.
7. Group-tab × lists every member in the confirm.
8. Every iOS REST client remints once on 401.
9. `tether device token` stays, and is honest in help + output.
10. User-facing docs and leftover password comments/test names are updated.

## Non-goals

Out of this spec (still true of 4.0, not this pass):

- CORS allowlist (still `*`).
- Dropping the plaintext default (`TETHER_TLS` still `both`).
- `tether rotate-identity`.
- Optional SAS.
- In-band Noise rekey trigger.
- Noise PTY metadata parity (`title` / `activity` / `diff` / `reset` frames).
- Registering `tether://pair` as an OS URL handler (QR is scanned inside the
  app only).
- IPv6 pairing-address parsing beyond whatever `validateAddress` already does.

## Decisions (locked)

| # | Choice |
|---|---|
| Pairing URL | Port implies scheme. Bare host, no port → `8085` + `http`. Explicit `http(s)` / `ws(s)` wins. |
| QR | Implement a QR in `tether pair`. Keep the iOS scanner. |
| Revoke live | Drop that device’s Noise (and leftover REST WS) subscribers. Holders/PTYs keep running. |
| Revoke push | `authDeviceId` on push register; revoke deletes matching push rows. |
| Last device | Warn and proceed. |
| Focus | `{t:'focus', id, focused}` on Noise (per-session, matching WS semantics). |
| IK oracle | Collapse unauthorized to handshake. Tests assert they are indistinguishable on the wire. |
| Group kill | Title “Kill N terminals in this group?” Body: one line per member title. |
| iOS 401 | One authorized-fetch helper for every iOS REST client: invalidate + remint once, then retry. |
| `device token` | Keep. List in help. Token only on stdout; device id + “revoke when done” on stderr. |
| Docs | User-facing docs **and** leftover password comments/test names. |

## Architecture

### 1. Pairing URL rule (desktop + iOS)

One function of meaning, implemented twice (TS + Swift) with identical cases
and tests:

```
parsePairTarget(raw) -> { scheme: 'http' | 'https', host, port, wsUrl }
```

- Trim. If `raw` contains `://`, keep that scheme (`http`/`https`/`ws`/`wss`;
  map `ws`→`http`, `wss`→`https` for the stored REST scheme).
- Else no scheme: look at the port.
  - `80` or `8085` → `http`
  - `443` or `8443` → `https`
  - any other port, or no port → `http`
- No port after parsing:
  - scheme `https`/`wss` → **443** (not 8443)
  - scheme `http`/`ws` or inferred `http` → **8085**
  - bare host with no scheme and no port → **8085** + `http`
- Persist `HostScheme` / profile port from **what was used**, not a hardcoded
  8443.
- Noise pairing WebSocket: `https` → `wss://host:port/api/noise/pair`,
  `http` → `ws://host:port/api/noise/pair`. Desktop must stop stripping
  `https`/`wss` and rebuilding `ws://`.

`PairDeviceLogicTests` that expect `https://192.168.1.9:8085` from a bare
`192.168.1.9:8085` are wrong under this rule; they change to `http`/`ws`.

### 2. Pairing QR

After `/control/pair/open` succeeds, `tether pair`:

1. Prints the grouped 12-char code (unchanged).
2. Prints the server fingerprint (unchanged).
3. Prints a UTF-8 block QR whose payload is
   `tether://pair?code=<grouped>&host=<urlencoded-url>`
   where `<grouped>` is `groupPairCode(code)` (`7QF4-KM9P-X3TV` — `PairPayload.parse`
   normalizes dashes), and `<urlencoded-url>` is the percent-encoded
   `http(s)://<first-non-loopback-IPv4>:<port>`. Listener topology:
   `TETHER_TLS=only` → TLS port (default 8443) + `https`; otherwise plaintext
   port (default 8085) + `http`. Render in a sibling of `pairCli.ts` (terminal
   blocks, no GUI). Add a workspace dependency only if no in-tree encoder exists.
4. Also prints that URL as text (decoded, copyable) so a desktop can paste it.

The iOS scanner already parses this via `PairPayload.parse`. Do **not**
register an OS handler for `tether://pair`. If no non-loopback IPv4 exists,
skip the QR, keep printing the code, and say so in one line.

### 3. Revoke: live channels

Maintain a process-local registry: `deviceId → Set<closable>` of live Noise
session sockets (and any leftover REST `/api/ws` subscribers tagged with the
same device id). Insert on successful IK (and on REST WS upgrade once the
bearer is verified). Remove on socket close.

`revokeDevice(target)`:

1. Resolve the row (unchanged).
2. `DELETE FROM auth_devices`.
3. Close every closable in the set for that id; each close unsubscribes PTY
   subscribers the way a client disconnect already does. **Do not** kill
   holders or `POST /api/sessions/kill`.
4. `DELETE FROM push_devices WHERE auth_device_id = $id`.
5. If `deviceCount()` is now 0, the **CLI** prints a warning that this was the
   last device and that `tether pair` is the recovery path, then still
   returns ok. The GUI revoke confirm is unchanged (no second modal).
6. Return the revoked row (unchanged).

`applyDevicesMessage` for `devices.revoke` calls this same function (no
second path). iOS `DevicesView` copy that assumes the server tore the
session down becomes true.

### 4. Revoke: push `auth_device_id`

Append a migration: `push_devices.auth_device_id TEXT NULL` (do not rewrite
an applied migration).

`authMiddleware` on a successful `verifyToken` sets `deviceId` on the Hono
context. `POST /api/push/register` writes that id onto the row. Re-register
from the same token updates the id.

Rows with `auth_device_id IS NULL` (pre-migration phones) are **not** deleted
on revoke. They go away when that phone re-registers (upsert sets the id) or
when the operator unregisters. Stolen-phone revoke of a never-re-registered
4.0.x push row is accepted: the live Noise drop in §3 is the shell cutoff;
push ciphertext stays decryptable only with the device’s push key, which the
stolen phone already has.

### 5. Noise focus frames

Old `/api/ws` is one socket per session, so `{type:'focus', focused}` needs
no id. Noise muxes many attachments on one channel (`input`/`resize` already
carry `id`). Same **semantics** as WS — this client’s view of **one**
session — so the Noise frame is `{ t: 'focus'; id: string; focused: boolean }`.
A missing or unknown `id` is ignored (do not tear the session). Do **not**
fan the flag across every attachment: that would mark sibling desktop tabs
focused and suppress their waiting push.

`makeSubscriber` starts with `focused = false`. `applyMessage` on `focus`
calls `setSessionFocus(id, sub, focused)` for that attachment only.

iOS `TerminalPipeline.sendFocus` seals `{t:'focus', id: noiseSessionId,
focused}` (it is a no-op today). Foreground / active session → `true`;
background / inactive / disconnect → `false` (send `false` **before**
dropping the socket). Desktop Noise pump sends the same on window/tab
focus, keyed by the tab’s session id.

A client that never sends `focus` stays unfocused → waiting push is **not**
suppressed. That is the safe default for a backgrounded phone that kept its
socket.

### 6. IK oracle

`acceptReconnect`: missing or revoked registry lookup throws
`ChannelError('handshake')` — the same code as a crypto failure. Do not
throw `'unauthorized'` from that path. Drop the unused `'unauthorized'`
variant from `ChannelError` if nothing else throws it (pairing denial stays
`'rejected'`).

`/api/noise/session` close the socket with the **same** status/body it
already uses for handshake failure. Tests: a finished IK from an unknown
pubkey and a truncated/garbage handshake produce equal close frames (status
+ payload bytes).

Internal logs may still say “registry miss” on the server. The wire must
not.

### 7. Group-tab kill copy

`SessionModals` (or the confirm already used by `onRequestKillMembers`):
when `members.length >= 2`, title is `Kill ${n} terminals in this group?`
and the body is one line per member title (the same labels `groupLabel`
would join). Solo kill copy is unchanged. Behaviour is unchanged: confirm
kills every member; pane close still does not kill.

### 8. iOS 401 remint

Extract the `NativeHostClient.sendAuthorized` one-shot (401 →
`invalidateBearer` → remint → retry once; second 401 surfaces) into the
shared `HostBearerSource` helper every REST client uses: Config, Git, Push,
Workspace, and NativeHostClient. Desktop `execute_authed` is already this
shape; do not rework it unless a call site still uses a password-era path.

### 9. `tether device token`

Keep the verb. `tether help` / `tether device` usage lists `token [name]`.
On success:

- **stdout:** the bearer only (pipe-friendly, unchanged).
- **stderr:** `Issued token for <id> (<label>). Revoke with: tether device revoke <id>`

No `--yes` flag.

### 10. Docs and leftover password comments

User-facing:

- `docs/updating.md`: 3.x → 4.0 is a hard cutover. After `tether update`,
  every client 401s until `tether pair` per device. The old password is
  ignored. Update the apps too.
- `docs/getting-started.md`: keep “prints a QR”; it becomes true. Pairing
  address examples follow §1 (`host:8085` is plaintext).
- `apps/server/README.md` Security: delete “the password gates access”.
  Access is per-device tokens minted over Noise.

Comment / test-name sweep (not a behaviour change): any comment, README
line, or test name that still teaches shared-password / `set-password` /
`PairingView` / `authMode(for:)` / argon2 in the DB. Known sites: 
`routes/noise.ts`, `db.ts`, `PairDeviceView.swift`, `SessionStore.swift`,
`PushRegistrar.swift`, `ConfigClient.swift`, `NoiseTokenCache.swift`,
`apps/server/README.md`, `crates/tether-core/tests/e2e_sessions.rs`
(`rejects_a_wrong_password_*` → token/bearer wording).

`SessionConfig` in `crates/tether-core` is already `bearer` — do not rename
it again. Do not keep a dual password/token comment.

## Error handling

- Pairing URL parse failure: existing client error strings (“Enter a valid
  code and host address.” / desktop `parsePairAddress` `reason`). No new
  toast taxonomy.
- QR skipped (no IPv4): one line on stderr; pairing still works by typing
  the code.
- Revoke of unknown target: unchanged `RegistryError`.
- Focus frame with a non-boolean `focused`, or a missing/unknown `id`:
  ignore the frame; do not tear the session (same “never throw out of the
  loop” rule as `devices.revoke`).
- 401 remint: one retry. Second 401 is the existing auth-failed surface.

## Testing

Server (`bun --cwd apps/server run test`):

- Pairing-rule unit tests live next to the TS helper if one is extracted
  for the CLI QR host; otherwise iOS/desktop own the parse tests.
- Revoke: live Noise session for device A, revoke A, assert the channel
  closes and `writeToSession` from that subscriber stops; holder still
  listed; token for A is 401; device B unaffected. Last-device revoke
  prints the warning (injectable `log`).
- Push: register with a token whose `sub` is A, revoke A, that push row is
  gone; a null-id legacy row is left.
- IK: unknown pubkey close ≡ garbage-handshake close.
- Focus: subscriber starts unfocused; `{t:'focus',id,focused:true}` then
  `sessionFocused(id)` is true; `false` clears it; a second attachment on
  the same channel is unchanged.

Desktop:

- `parsePairAddress` matrix: `host`, `host:8085`, `host:8443`,
  `https://host`, `https://host:8443`, `http://host:8085`, `wss://host:8443`.
- Group-kill confirm strings for a 2-member view (pure function if the copy
  is extracted; otherwise a small helper).

iOS (macbuild):

- `serverURL` / `hostAndPort` matrix matching §1.
- `PairPayload.parse` of the QR URL `tether pair` emits.
- Authorized-fetch helper: 401 then 200 remints once; double 401 does not
  loop.

CLI:

- `parseDeviceArgs(['token'])` / help text includes `token`.
- `runDevice` token path: stdout is the token, stderr contains the id (deps
  injected).
